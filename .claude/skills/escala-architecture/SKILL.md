# Escala architecture

Escala is a three-tier token system. Agents that skip a tier produce UI that looks right in one brand and breaks in the next.

```
PRIMITIVES                    SEMANTIC ROLES                    COMPONENTS
colour ramps 1–12 (+ alpha)   color.<group>.<role>  per THEME   recipes / screens
Dimension ladder (px)    →    <family>.<role>  per VIEWPORT  →  read ROLES only
font sizes · weights          type.<role>      per VIEWPORT
```

- A **design system** holds **brands**; a brand ships **themes** (Light, Dark).
  Colour roles have one value per theme. Figma calls these "modes".
- Lengths and type do **not** change with the theme; they change with the
  **viewport** — Desktop · Tablet · Mobile.
- Every role is an ALIAS of a primitive. Many colour roles are **solved** per
  theme (the hex is computed for contrast against the brand's own ramps), so
  the same role name is a different hex in every brand. That is the point.

## Rules

1. **Components read roles, never primitives and never hex.** No
   `--color-accent-9`, no `#7f56d9`, no `--radius-lg`, no `16px`, no
   `--font-size-text-sm` in a component. If a value cannot be expressed with
   a role, that is a missing role — say so and propose one; do not hard-code.
   (Anatomy a role does not cover may use a Dimension step snapped to the
   scale — e.g. a 2px icon gap — never a free px.)
2. **Never invent a role name.** Use only names in the references. Verify a
   name before using it; a plausible-sounding *color.surface.card* or
   *spacing.padding-lg* does not exist.
3. **Never copy a resolved hex between systems.** Resolve from the brand's own `variables.css` / `tokens.json`. Solved roles (`{on:…}`, `{step:…}`, `{ui:…}`… in the reference) move with the brand by design.
4. **A state is a role, never opacity or a filter.** Hover / pressed /
   disabled each have their own role (`action.primary.hover`,
   `action.disabled.default` + `content.disabled`). Don't `opacity: .5` a
   disabled button or `brightness(0.9)` a hover.
5. **Alpha roles are already translucent** (`surface.selected`,
   `surface.overlay`, `status.*.surface`, `action.ghost.*`, `border.subtle`…).
   Never add opacity on top; they composite correctly on any surface.

### Colour pairs — a fill always travels with its ink

| Fill | Ink on it |
|---|---|
| `surface.page` / `surface.layer-1` / `surface.layer-2` | `content.primary`, `content.secondary` |
| `action.primary.default\|hover\|pressed` | `content.on-action` (solved: may be near-black — never assume white) |
| `action.secondary.default\|hover\|pressed` | `content.on-secondary` |
| `action.ghost.*`, outline buttons | `content.primary` |
| `action.disabled.default` | `content.disabled` |
| `surface.inverse` (tooltip, snackbar) | `content.inverse` |
| `status.<sev>.surface` (tint: alert, banner) | `status.<sev>.content` + edge `status.<sev>.border` |
| `status.<sev>.surface-solid` (badge, destructive button) | `status.<sev>.on-solid` |
| `surface.accent` | `content.accent` |

`<sev>` = `critical` · `warning` · `success` · `info`. All four have the same
role shape — use the same structure for every severity.

`content.subtle` is for placeholders and decoration only — never information.
Links use `content.link.default` / `.hover`, not `content.accent`.

### Borders — pick by JOB, not by weight

| Job | Role |
|---|---|
| Hairline, table rule, quiet divider | `border.subtle` |
| Card / panel edge | `border.default` |
| Emphasised container edge | `border.strong` |
| Resting outline of an input, select, checkbox, outline button | `border.control` → hover `border.control-hover` |
| Invalid / warning / valid field | `status.<sev>.border-strong` |
| Edge of an alert or banner | `status.<sev>.border` |
| Keyboard focus | `border.focus` (the boundary) **plus** `border.ring.default` (the halo outside it) |
| Selected / brand-coloured stroke | `border.accent` |

Width is a separate token: `stroke.divider`, `stroke.control`, `stroke.focus`.
There is ONE focus ring, also on an invalid field — focus wins over error.

### Dimensions

- **Radius has three independent axes.** Boxes (`radius.container`,
  `radius.overlay`), Fields (`radius.action`), Selectors (`radius.control`).
  `radius.pill` means "a circle" (avatar, badge, switch). Never give a card
  the button's radius to "match".
- **Nested radius:** a child flush inside a parent with padding p uses
  r = R − p. A button floating inside a card is not nested.
- **Spacing = air, Size = object.** Gaps between siblings → `spacing.gap-*`
  (tight < control < group < section). Padding inside → `spacing.inset-*`
  (control · surface · page; each has `-top|right|bottom|left`). Heights →
  `size.*` (`size.control` default, `size.compact` dense, `size.touch` mobile
  CTA, `size.hit` icon-only target). A fixed-height control takes only
  horizontal inset; its height comes from `size.*`.
- Checkbox / radio / switch glyph box → `selector.*`, not `size.*`.
- Stacked avatars → `spacing.overlap-*` (negative).
- Icons → `icon.small|medium|large`; they scale with control height.
- Spacing and radius roles step down on Tablet/Mobile inside the media
  blocks of `variables.css`. Read the variable; never hard-code the phone px.

### Typography

- Use `type.*` roles. Headings use the BODY family by default — size and
  semibold carry hierarchy; only `type.display` uses the heading font.
- Field label, placeholder, typed value and button label sit on one tier
  (`text-sm`). Don't make a button label larger than body copy.
- In CSS a role is five variables (`--text-<role>-font-size`, `-line-height`,
  `-font-weight`, `-font-family`, `-letter-spacing`); smaller viewports use
  the `-tablet` / `-mobile` twins. Set all five together, never only size.
- In Figma apply the text style `Type/<role>`.

## Building components in Figma

Use this when building or editing a component, a component set or a UI kit
in a Figma file. The component's own contract (from the user, or the file)
decides its STRUCTURE; this skill decides every VALUE.

1. **Find the variables, never create them.** The Escala plugin syncs the
   foundations into the file: collections `Color Semantics`,
   `Dimension Semantics`, `Typography` (plus `Color Primitives` and
   `Dimension Primitives`, which components never bind), text styles
   `Type/<role>` and effect styles `Shadow/<step>`. Look a variable up by its
   exact name (local or from the library). If one is missing, **stop and say
   which name is missing** — do not create a variable, do not put a hex or a
   px in its place.
2. **Bind everything, leave no raw value.**
   - Fills and strokes → a `Color Semantics` variable (never a primitive).
   - Padding, gap (item spacing), corner radius, fixed width / height and
     stroke weight → a `Dimension Semantics` role (`Spacing/…`,
     `Radius/…`, `Size/control-*`, `Size/selector-*`, `Size/icon-*`,
     `Size/target-min`, `Stroke/…`). There is no `role/` segment and no
     `Icon/` or `Selector/` group.
   - Text → apply the text style `Type/<role>` (all facets at once).
   - Elevation → the effect style `Shadow/<step>`.
   - Use auto layout so padding and gap are real properties you can bind.
3. **Themes and viewports are MODES, not copies.** Check Light / Dark by
   switching the `Color Semantics` mode on the frame, and Desktop / Tablet /
   Mobile by switching the `Dimension Semantics` and `Typography` modes. Never
   make a Light and a Dark variant of a component, never duplicate a value per
   mode.
4. **States are variants, each with its own roles.** `State` = Default ·
   Hover · Pressed · Focused · Disabled (only the ones the contract lists);
   each state binds its own role (`Action/primary/hover`,
   `Action/disabled/default` + `Content/disabled`, focus =
   `Border/focus` + `Border/ring/default`). No opacity for a state.
5. **Contract vs Escala.** The contract owns anatomy, variants, properties,
   layer names and behaviour. Escala owns every colour, length and text style.
   If the contract needs a value no role covers, do not hard-code it: name it
   under **Missing roles** with the closest existing role.
6. **Report at the end:** a table per component of layer → property → bound
   variable or style, then any Missing roles. A layer with an unbound value
   is a bug to fix before finishing.

## Quick map — "I need …"

| Need | Role |
|---|---|
| Page background | `color.surface.page` |
| Card | `color.surface.layer-1` + `border.default` + `radius.container` + `spacing.inset-surface` |
| Popover / menu / modal | `color.surface.layer-2` + `radius.overlay` + a shadow; scrim `color.surface.overlay` |
| Body text / secondary text | `color.content.primary` / `color.content.secondary` + `type.body-md` |
| Primary button | `action.primary.*` + `content.on-action` + `radius.action` + `size.control` + `spacing.inset-control` + `type.button` |
| Text field | `surface.input` + `border.control` (hover `border.control-hover`, focus `border.focus` + `border.ring.default`) + `radius.action` + `type.placeholder` / `type.label` |
| Selected row | `color.surface.selected` |
| Switch off track / progress track | `color.surface.muted` |
| Error alert | `status.critical.surface` + `status.critical.content` + `status.critical.border` |
| Delete button | `status.critical.surface-solid` (+ `-hover` / `-pressed`) + `status.critical.on-solid` |
| Form helper / validation text | `type.helper` + `content.secondary` or `status.<sev>.content` |
