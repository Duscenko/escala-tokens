# DEC-2026-11-16-001 · `Radius/item` accepted, fourth radius axis "Items"

- **Date:** 2026-11-16 · **Owner:** Cesar Durango · **Status:** Decided (made Figma-first, ported to code in this loop)
- **Findings:** none (a new role, not a defect)

## Context
Segments of a `SegmentedControl` sit in a track on `Radius/action` (12) inset by `Spacing/gap-tight` (4). A segment at 12 is not concentric with its track; at 4 it reads square. Sidebar menu buttons have the same relation to a flush list.

## Options
1. Reuse `Radius/control` (4): too square for a segment, and it is the selector axis.
2. Reuse `Radius/action` (12): breaks concentricity (12 − 4 = 8).
3. Add `Radius/item` = 8.

## Decision
Option 3. `radius.item` = 8, CSS `--radius-item`, Figma `Radius/item` (primitive `8`). Fourth radius axis, "Items".

**Rule.** `radius.item` is for an element nested in a TRACK or a FLUSH LIST: parent radius − inset (`SegmentedControlItem`: track 12 − `gap-tight` 4 = 8; `SidebarMenuButton`). A row inside an OVERLAY is not an item: it uses `radius.action` (12) with overlay inset `Spacing/inset-control` (24 − 12 = 12).

## Consequence
`tokens` (layoutTokens), recipes `SegmentedControlItem` and `SidebarMenuButton`, the role catalogue (`references/dimension-roles.md`, escalatokens.com Radius family), `escala-architecture` skill.
