# DEC-2026-11-18-002 · Component contracts published as static files, no MCP

- **Date:** 2026-11-18 · **Owner:** Cesar Durango · **Status:** Decided
- **From:** the AI-readiness review of 2026-11-18 (flag 5: "hosted MCP was removed; outside agents get tokens but no component guidance").

## Context
Outside the repo an agent could read the token schema and `GET /api/tokens`, but not the 117 component contracts in `spec/contracts/`. The review first proposed shipping them in the offline agent package. That package belongs to each user's generated token system, and the contracts describe Escala's own components (`code.files` point at this repo), so they do not belong there. The hosted MCP stays deleted (CLAUDE.md, "Do not bring back").

## Decision
`spec/contracts/` is copied at build time to `/docs/agent-native/contracts/` on escalatokens.com, beside the token schema: `index.json`, then `<Key>.json`. Static, read-only, nothing committed twice.

## Consequence
- `scripts/contracts-publish.ts` + the `publishContracts` plugin in `vite.config.ts` (build: emitted assets; dev: served from `spec/contracts/`).
- `llms.txt` and `AGENTS.md` name `https://www.escalatokens.com/docs/agent-native/contracts/index.json`.
- `src/lib/__tests__/contractsPublish.test.ts`: every indexed contract ships byte for byte, and both routers name the URL.

## Rollback
Remove the plugin from `vite.config.ts` and the two router lines.
